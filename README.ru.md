# Trosna

**Trosna** — формат файлов для временных рядов (`.trosna`) с безопасной по
памяти реализацией на Rust, утилитой командной строки и пакетом для Python.
Цель — чтобы файл создавался и читался так же просто, как CSV, но данные
хранились так, как их хранят СУБД временных рядов: по столбцам, с кодированием,
подобранным для меток времени и измерений.

[English version](README.md) · [**Пошаговое руководство**](docs/GUIDE.ru.md) ·
[Спецификация формата](docs/SPEC.md) · [Проектные решения](docs/DESIGN.md) ·
[Примеры](examples/) · [Демонстрационный репозиторий](https://github.com/89605502155/trosna-file-demo)

* **Столбцовый и компактный.** Каждый блок хранит метки времени и каждый
  столбец отдельно; для каждого сегмента выбирается самое короткое из
  кодирований: delta-of-delta, битовая упаковка разностей в духе TS_2DIFF,
  XOR-кодирование Gorilla, RLE и словарь, — после чего данные при необходимости
  сжимаются LZ4 или Zstandard.
* **Один файл — много устройств.** Файл содержит любое число *устройств*
  (таблиц строк с метками времени, у каждой свои столбцы, единица времени и
  часовой пояс).
* **Редактирование с историей.** Точки можно добавлять, изменять и удалять, а
  интервалы времени — *размечать* (метки с подписью и комментарием). Каждое
  изменение — атомарный коммит; любая прежняя версия остаётся доступной для
  чтения (`as_of`), пока файл не уплотнён. Коммиты связаны цепочкой хэшей
  SHA-256, поэтому подмена истории обнаруживается.
* **Дозапись, устойчивая к сбоям.** Файл — журнал кадров с контрольными
  суммами, в который только дописывают. После сбоя файл читается со всеми
  завершёнными коммитами; следующий писатель (или `trosna recover`) отрезает
  незавершённый хвост.
* **Безопасность.** В библиотеке нет `unsafe`-кода и зависимостей на C; каждая
  длина, прочитанная из файла, сверяется с ограничениями и размером файла до
  выделения памяти, а повреждённые данные дают ошибку, а не аварийное
  завершение.
* **Экосистема Python.** pandas, Polars и PyArrow читают и пишут файлы Trosna
  через Apache Arrow без копирования значений; чтение и запись идут пачками,
  потоком.

> Состояние: версия 0.1, версия формата 1.0 (черновик). До версии 1.0
> библиотеки формат ещё может меняться.

## Зачем

В обзоре *«Обзор структур данных и форматов файлов для хранения и передачи
временных рядов с учётом их поддержки в экосистемах Python и Rust»*
(А. О. Ферубко, О. Д. Казаков, БГИТУ, 2026) показано, что для временных рядов
лучше всего подходит столбцовое хранение с раздельным кодированием меток
времени и значений — полнее всего оно реализовано в Apache TsFile, — но у TsFile
есть поддерживаемые реализации только на Java и C++. Универсальные столбцовые
форматы (Parquet, Arrow) не учитывают специфику временных рядов, и дозапись в
них дорога, а научные форматы (HDF5, netCDF) доступны в Rust лишь через
библиотеки на C. Trosna развивает идеи TsFile на безопасном Rust и добавляет
то, что часто нужно измерительным данным: исправления без потери исходных
значений, размеченные интервалы и проверяемое происхождение данных. Подробности
и научная новизна — в [docs/DESIGN.md](docs/DESIGN.md).

## Командная строка

```sh
cargo install --git https://github.com/89605502155/trosna-file trosna-cli   # команда `trosna`

trosna convert sensors.csv sensors.trosna --device room1   # CSV → Trosna
trosna info sensors.trosna
trosna cat sensors.trosna --from "2026-10-08 10:00" --columns temperature
trosna update sensors.trosna --time "2026-10-08 10:00:20" temperature=21.8 -m "сбой датчика"
trosna annotate sensors.trosna --start "2026-10-08 10:00:15" --end "2026-10-08 10:00:25" --label "дверь открыта"
trosna log sensors.trosna
trosna diff sensors.trosna --from 1
trosna cat sensors.trosna --as-of 1 --format table
trosna convert sensors.trosna back.csv                       # Trosna → CSV
trosna verify sensors.trosna
```

При импорте CSV типы столбцов определяются автоматически; время читается в
формате ISO 8601 (первое смещение UTC становится часовым поясом устройства)
или как целое число от начала эпохи (единица угадывается по величине или
задаётся `--unit`). Файл обрабатывается пачками, поэтому его размер не
ограничен объёмом памяти. Все параметры: `trosna help <команда>`.

В утилите и в Python действуют одни правила для времени: время без смещения
UTC — это показание часов в часовом поясе устройства (в повторяющемся часе
берётся более ранний момент; время, пропущенное при переходе на летнее время, —
ошибка); время точки должно точно выражаться в единице устройства, а границы
диапазона, попавшие между двумя метками, округляются внутрь диапазона. Команды,
заменяющие файл, сначала пишут временный файл, поэтому сбой не портит
существующие данные.

## Python

```sh
pip install "trosna @ git+https://github.com/89605502155/trosna-file#subdirectory=python"
# или в клоне репозитория: pip install maturin && maturin develop -m python/Cargo.toml
```

```python
import pandas as pd
import trosna

df = pd.read_csv("examples/sensors.csv", parse_dates=["time"])
trosna.write("sensors.trosna", df, device="room1")

trosna.read_pandas("sensors.trosna")
trosna.read_polars("sensors.trosna", start="2026-10-08 10:00:10", columns=["temperature"])
for batch in trosna.read_batches("sensors.trosna"):   # pyarrow.RecordBatch, потоком
    ...

f = trosna.open("sensors.trosna")
with f.edit(message="дверь была открыта", author="аналитик") as tx:   # один атомарный коммит
    tx.delete("room1", "2026-10-08 10:00:20")
    tx.annotate("room1", "2026-10-08 10:00:15", "2026-10-08 10:00:25", "дверь открыта")
f.read_pandas(as_of=1)     # данные в момент импорта
f.diff(1)                  # что изменилось после коммита 1
f.commits()                # история, связанная хэшами
```

## Rust

```rust
use trosna::{Batch, Column, CommitOptions, DataType, DeviceSchema, Reader, TimeUnit, Writer};

let mut writer = Writer::create("metrics.trosna")?;
writer.create_device(
    DeviceSchema::new("vm01", TimeUnit::Millisecond).with_column("cpu", DataType::Float64),
)?;
writer.write("vm01", &Batch::new(vec![1_000, 2_000], vec![("cpu", Column::from(vec![0.31, 0.35]))])?)?;
writer.commit_with(CommitOptions::message("первые измерения"))?;
writer.close()?;

let reader = Reader::open("metrics.trosna")?;
let cpu = reader.query("vm01")?.columns(["cpu"]).time_range(1_000..=1_500).collect()?;
```

Адаптер `trosna-arrow` превращает запросы в `RecordBatchReader` Apache Arrow
для DataFusion и других инструментов на основе Arrow. Полный пример —
[crates/trosna/examples/quickstart.rs](crates/trosna/examples/quickstart.rs).

## Сравнение с другими форматами

Для медленно меняющегося ряда показаний датчика (значения с шагом 0,01,
период 1 с) файл `.trosna` занимает **2,86 байта на точку** при 10 млн точек —
на 14 % меньше, чем Arrow IPC, на 22 % меньше, чем Parquet, и на 25 % меньше,
чем Apache TsFile (все со сжатием Zstandard). На очень коротких рядах
преобладают постоянные накладные расходы файла, и наименьший объём даёт
сжатый CSV. Методика, все результаты и сценарии — в папке
[benchmarks/](benchmarks).

## Структура репозитория

```
crates/trosna        основная библиотека: формат, кодирования, запись, чтение, история
crates/trosna-arrow  преобразование в Apache Arrow и обратно
crates/trosna-cli    утилита командной строки `trosna`
python/              пакет для Python (расширение на PyO3 + слой на Python)
docs/                спецификация формата и описание проектных решений
testdata/            эталонные файлы, фиксирующие двоичный формат
benchmarks/          сравнение с CSV, Parquet, Arrow, HDF5, TsFile
examples/            примеры: CSV, Python, командная строка
```

Тесты включают проверку свойств (property-based) для всех кодирований,
модельное тестирование семантики редактирования относительно эталонной модели,
обрезание файла на каждом байте, случайные искажения байтов, эталонные файлы и
интеграционные тесты утилиты и пакета Python:

```sh
cargo test
maturin develop -m python/Cargo.toml && pytest python/tests
```

Минимальная версия Rust — 1.89; Python — 3.11 и новее.
